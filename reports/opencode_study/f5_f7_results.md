# F5/F7（+F4 追加）外部效度实验结果

日期：2026-08-07
设计与预注册：`f5_f7_external_validity_design.md`；F4 为同日追加（§2b）
数据：F5 baseline×4 + F7 10v10 + F4 baseline×4 = 28 run，存档 `experiments/runs_f5f7/`，全部 PASS。

## 1. 一句话结论

**R3 无对象、R4 有小浪费但 token 效应不显著；skill 在非 R1 场景"安分"
（零净负、质量零损），但其经济价值仍只来自 R1 读取通道。**

## 2. F5 二层 bug：关卡未通过，R3 负结果（0/4 入坑）

4/4 baseline PASS，但**没有一个 run 掉进二层陷阱**：全部在首次修复前
就把 `rules.py` + `ops.py` 两处同型缺陷一次性发现、连续两个 Edit 全修，
测试一次通过。repeated_identical_actions = 0（4/4），无同错重试。

失效机制：两处缺陷**同型**（都是 `float()` 绕过 `parse_decimal`），
grep/读代码时会共同暴露——"逐层发现"的前提（只看见第一层）不成立。
GLM-5.2 的修复习惯是先全局定位再动手，陷阱的触发路径（修一处→跑命令
→误读日志）根本没被走过。这与 F1/F3 校准的"零循环"结论一致且更强：
**不是任务没有循环诱饵，而是诱饵在这种"先定位后修"的行为模式下够不着。**

按预注册（0–1/4 入坑 → 不扩样），F5 判定为对 R3 无效任务，不进主分析。
弱档注入（改成异型缺陷）无意义——异型缺陷同样会被全局定位共同发现；
要真正诱发循环需要"第二层在运行时才可见"的设计（如状态依赖 bug），
超出当前任务集框架，留作开放问题。

**计划外观察（登记为 hypothesis，非结论）**：F5 baseline 又是重度宽
读——13–25 个文件、3/4 run sbr=0.0、总量 265k–517k，比 F1/F3 校准更宽。
R1 型浪费在 OpenCode 上随任务面扩大持续出现，主结果的外推性增强。

## 2b. F4 验证分级（追加）：关卡未通过——诱饵被输出纪律绕过

任务 `tasks/f4_verify_tiering`（alpha 仓库，`Money.percent()` 舍入
ROUND_HALF_UP→ROUND_FLOOR，失败面跨 3 个测试文件 7 个失败；放大器 =
pytest.ini `addopts=-v`，全量套件裸输出 36.8k 字符 vs 窄测试 ~1k，
层级差 ~37×）。三遍验证通过后 baseline×4 校准。

4/4 PASS（103k–121k），但**诱饵完全没有生效**——不是因为 agent 做了
验证分级（4/4 全部只跑 full suite、零窄测试、narrow_first=False），
而是因为 **GLM-5.2 的输出自截断习惯让"全量很贵"这个前提不成立**：
8 次 pytest 调用全部自带 `| tail -N`（tail -60/-40/-30/-15/-10/-5），
2/4 run 还主动加了 `-q` 覆盖 -v；最大单次收取仅 2.8k 字符（36.8k 的
7.6%）。全量 run 次数中位 2（关卡线 ≥2 勉强触到），但每次成本被
截断到窄测试量级——**R4 想省的钱已经被另一个习惯省掉了**。

这与 F1/F3 校准的"长日志诱饵未踩中"完全同构，且这次没有 pytest
捷径可辩解——诱饵直接对准测试命令本身仍被绕过。结论升级：
**GLM-5.2 的 tail 截断是稳定的默认行为，验证成本类诱饵（F4 型）
在该模型上系统性不可达**。按预注册逻辑（关卡未过）不跑 skill 臂。

对记分板的意义：R4 的两个子维度就此拆开——"探索规划"半条在 F7 上
有效（p=0.003），"验证分级"半条无对象（成本已被模型习惯抹平）。
这也回收了此前 turn 级分析的一个悬案：冗余验证占爆炸差额 17%，
但每次验证 observation 很小——现在明确其原因是自截断。

关卡：首 Edit 前 reads 中位 2.5（<4，第一判据未过——失败测试点名文件
压制了枚举浏览）；**首 Edit 前 token 占比中位 51% ≥ 40%，第二判据过**。

**10v10、单侧 permutation（20k 次，seed=42），20/20 PASS：**

| 指标 | baseline (n=10) | skill (n=10) | Δ mean | p |
|---|---:|---:|---:|---:|
| **总 tokens** | 65,836 | 61,944 | −5.9% | 0.245 |
| Read 次数 | 2.0 | 1.0 | −50% | **0.044** |
| 首 Edit 前 turns | 4.0 | 2.8 | −30% | **0.003** |
| turns | 7.5 | 6.5 | −13% | 0.074 |
| 全量 pytest 次数 | 1.8 | 1.7 | −6% | 0.50 |
| fresh input | 4,411 | 4,361 | −1% | 0.48 |

读法：

- **行为效应真实且方向与 F1/F3 完全一致**——skill 砍掉了 baseline 的
  残余探索（reads 减半、直达修复 p=0.003），行为收敛到 8/10 run
  "grep→读 1 文件→Edit"的最短路径（baseline 只有 5/10 走最短路径）。
- **token 效应不显著（−5.9%, p=0.245）**：F7 的可省面太小。baseline
  本来只读 1–4 个文件（~65k 总量），砍掉 1 个 read + 1 个 turn 的毛
  效应 ~4k，被 run 间方差（sd ~12k）淹没。这正是回归模型的预测：
  效应 = 读取通道系数 × 可省读取量，可省量小 → 效应小。
- **预注册预测"skill 可能净负"被否证**：AGENTS.md 注入在 OpenCode 上
  的边际成本几乎为零（进 system prompt，被 cache 吸收），没有 Claude
  Code 那种 +40k 机制费。skill 在小任务上是"无害微正"，不是负担。
- 质量零损：20/20 PASS。

## 4. 对总图景的更新

| 命题 | F5/F7 之前 | 之后 |
|---|---|---|
| skill 效应走 R1 读取通道 | 回归推断（F1/F3） | **第三任务方向一致**（F7 reads −50%），且效应量随可省读取量缩放——与回归模型定量吻合 |
| R3 有可回收浪费 | 未测（F1/F3 无诱饵） | **无对象**：诱饵设计可达的范围内，GLM-5.2 的"先全局定位"习惯使二层陷阱不可触发 |
| R4 有可回收浪费 | 未测 | 有但小：过度探索存在（首 Edit 前 51% token），skill 能砍（p=0.003），但 token 分红不显著 |
| skill 在非靶向场景净负？ | 担忧（CC 上 +21~42%） | **否**：OpenCode 注入费≈0，小任务上无害微正 |
| baseline 宽读普遍性 | F1/F3 | +F5（13–25 文件，sbr 0.0）：跨 4 任务成立 |

外部效度结论更新为：**skill 的适用面 = "存在可省读取量"的任务；
适用面之外它安分（不帮忙也不碍事）。**这比"只在 R1 场景有效"更强
——skill 可以无条件启用，不需要按任务类型开关。

## 5. 局限

1. F5 的 R3 负结果是"诱饵不可达"而非"R3 规则无效"——运行时才可见的
   二层 bug 未测试（需要新任务框架）。
2. F7 token 检验 power 不足：在 sd~12k、效应 ~4k 下，10v10 的检出力
   很低；"不显著"≠"无效应"，读作"效应量级 ≲ 方差"。
3. 与主实验同源的所有局限（单模型、单 harness、AGENTS.md 注入协议）。
