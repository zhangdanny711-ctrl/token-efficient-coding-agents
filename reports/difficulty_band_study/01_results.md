# 难度带质量权衡实验 — 结果:目标难度带不可达,质量天花板未破

日期:2026-08-07。运行归档:`experiments/runs_difficulty_band/`(48 runs:v1_cal/ 12 + v2_cal/ 12 + v3 baseline 12 + v3 skill 12,见 §4a)。
预注册设计:`00_design.md`(含 §4a/§4b 两次修订,均为预注册允许的"all-pass → 加难"分支)。

## 1. 一句话结论

**三轮递进加难(移除失败测试锚点 → 移除复现代码 → 纯散文症状)后,GLM-5.2/OpenCode baseline
在全部 36 个校准 run 中 36/36 PASS——50–80% 目标 pass 带在"真实单-commit bug + 完整回归套件"
任务族内不可达。** 按预注册终止规则(§4b),主批不扩容,skill arm 不运行;本实验的可发表结论
是一个**弱上界**:在此任务族内检测不到 baseline 质量失败,因而"skill 少读导致质量损失"的
假设无法在该难度范围内获得检验面——与 eco 批次 48/48 的天花板观察一致,且这次是主动
压力测试后仍未击穿。

## 2. 任务与三轮协议

3 个任务,取自 alternates 池最难档,均两向机械验证(buggy=FAIL / fixed=PASS):

| id | 库 | 缺陷 | 难度设计 |
|---|---|---|---|
| H1 | toolz (~3.7k LOC) | partition_all 假 `__len__` 哨兵切片 (B2, 5a7e078c) | 正确判据非显然,要求精确 raise LookupError |
| H2 | boltons (~17k LOC) | ParsedException 截断 traceback,2-hunk (B3, 8a2a93d8) | 已手工验证浅修(单 while guard)过不了 holdout |
| H3 | dateutil (~7.6k LOC) | **合成双 bug**:B1 分隔符状态机 (34906dc) + B13 T24:00 回注 (424a438b) | 状态机重写 + 559 个邻近回归测试压力 |

| 轮 | agent 可见的信息 | 结果 |
|---|---|---|
| v1 | fix-commit 测试在 workspace 内(红测试锚点) | 12/12 PASS |
| v2 | workspace 测试 = parent 版(全绿);task.md 给行为规格 + **可执行复现片段**;holdout 隐藏 | 12/12 PASS |
| v3 | 复现片段也移除,症状纯散文(用户报告口吻) | 12/12 PASS |

## 3. 核心数据:质量不降,成本翻倍再翻倍

median tokens / median turns(n=4/格):

| 任务 | v1 | v2 | v3 | v3/v1 |
|---|---|---|---|---|
| H1 | 185k / 11.5 | 359k / 17 | 698k / 20 | ×3.8 |
| H2 | 154k / 11.5 | 347k / 15.5 | 644k / 20.5 | ×4.2 |
| H3 | 493k / 17 | 764k / 21.5 | 1387k / 32 | ×2.8 |

**distinct_files_read 全程平坦(median 2–3.5,三轮无趋势)——信息剥夺的全部代价进了
turns 通道,不是 reads 通道。** 机制:失去锚点后,agent 用"自建测试→迭代验证"补偿
(v3 run 普遍先从散文症状构造本地复现,再进入常规修复循环;单 run 最高 1.54M tokens、
32 turns),但从不多读文件。这与 R1 归因(reads⊥turns,r=−0.25)和 F4/F5 的
"GLM-5.2 自带全局定位+自截断纪律"结论互相印证:**该模型的质量鲁棒性由 turn 预算
的弹性支撑,而非上下文摄入量**——也因此"skill 压 reads"不构成质量风险面。

## 4. 对 skill 主张的含义

1. **主张不升级也不降级**:预注册解释矩阵第 4 分支(gate 漏判/天花板未破)——难度带
   实验对"−36% 且质量无损"主张提供的是**一致性证据而非判定性证据**。178 个既有
   PASS-PASS run + 本实验 36 个高压 baseline PASS,质量损失如存在,其触发面在
   比"真实单-commit bug"更难的任务族(多文件架构级缺陷、无回归套件保护的探索式修改)。
2. **意外的正面发现(v2→v3 对比)**:信息剥夺的成本弹性巨大(×2–4 tokens)而质量弹性
   为零。对 skill 故事的意义:R1 压的是 reads 通道(廉价、无质量风险);任务侧信息
   质量决定 turns 通道(昂贵、但 GLM-5.2 用它换质量)。**两个通道正交,skill 不碰
   昂贵通道——这是"skill 无质量代价"的机制性解释。**
3. **功效诚实声明**:n=12/任务族只能排除很大的失败率(单任务 4/4 PASS 对真实失败率
   的 95% 单侧上界 ≈ 53%;三任务合并 36/36 上界 ≈ 8%)。"上界 8%"是本实验能给出的
   最强定量表述。

## 4a. 追加:skill arm sanity check(2026-08-07,用户要求,n=12)

用户质疑(合理):"baseline 全过,会不会正因为它没少读?skill 少读也许会挂。"36 个 baseline run
无法回答这个问题——skill 与高难任务的交互从未被直接观察。故追加 skill arm ×4/任务,
v3 协议(纯散文症状,最难档),与 baseline v3 严格同条件。

**结果:skill 12/12 PASS——"少读导致难任务失败"的尾部风险被直接排除**(双臂合并 48/48,
质量上界从"仅 baseline"升级为双臂)。reads 中位 2–3.5,与 baseline 持平:skill 在无可省
空间的任务上不强行砍读(与 F7/E2 的"安分"结论一致),自然也不制造信息饥饿。

**意外收获:skill 在最难档大幅省 token——分层中位 δ = −38.8%,置换检验 p=0.0102。**

| 任务 | baseline 中位 (n=4) | skill 中位 (n=4) | δ | turns |
|---|---|---|---|---|
| H1 toolz | 698k | 285k | **−59%** | 20→13.5 |
| H2 boltons | 644k | 340k | **−47%** | 20.5→15.5 |
| H3 dateutil | 1387k | 1246k | −10% | 32→25.5 |

机制注记:reads 无差 ⇒ 节省全部来自 **turns 通道**(三任务 turns 中位一致下降)。这与主实验
"R1/reads = 唯一杠杆、turns 不可控"的图景形成有趣张力:在 v3 高难条件下,baseline 的 turn
膨胀(自建测试→漫游式反复验证)存在**可观的可压缩部分**,而完整 skill(R3 停止规则 + R4
验证纪律)恰好压住了它。§3.8 曾留下"full 相对 r1only 的 turn 残余是协同还是噪声"的开放问题
——本数据是"turn 通道在高难条件下确实可由 prompt 压缩"的首个直接证据(n=12,方向一致,
p≈0.01;仍属探索性发现,机制归因到具体规则需要专项 ablation)。H3 效应最弱(−10%)与其
形态一致:双 bug + 559 回归测试的真实工作量下限高,可压缩的漫游占比小。

## 5. 局限

- 未能进入设计目标难度带——"skill 在 50–80% 带内的表现"仍是空白,只是该带在此任务族内
  不存在。skill arm 有 v3 条件下的 sanity check 数据(§4a,12/12 PASS),但那不是失败带内
  的对比。
- §4a 的 turn 通道压缩发现是探索性的(n=4/格,事后追加,非预注册终点),机制归因未做。
- 加难维度只走了"信息剥夺"一条路;未尝试架构级/多文件合成缺陷(工程成本高,且脱离
  "真实历史 bug"的生态效度框架)。
- v1/v2/v3 的 task.md 不同,token 数字跨轮不可与主实验直接比较(此处只做轮间相对比较)。
- H3 的双 bug 合成引入作者之手(回注代码是手写的),但两 bug 本身都是真实历史缺陷。
