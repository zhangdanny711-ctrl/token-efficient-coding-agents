# AI Coding 低 Token 方法：文献检索与筛选记录

检索日期：2026-07-20；Skill 专项补充检索：2026-07-21  
研究场景：固定 Coding Agent（z code）、固定模型（GM 5.2）、固定工具链  
研究类型：范围综述（scoping review），不是穷尽式系统综述

## 1. 研究问题

主问题：在不更换模型、不训练模型的前提下，哪些用户操作、上下文管理、流程编排和人机交互方法，能够在保持 AI Coding 任务质量的同时减少端到端 token 消耗？

子问题：

1. Token 主要消耗在哪些阶段、动作和上下文类型？
2. 指令或 issue 描述的哪些属性会影响任务成功与返工？
3. 如何选择、压缩和维护仓库级代码上下文？
4. 固定流程、自主 Agent、分解、规划、验证和重试如何影响质量与成本？
5. 人工澄清和审批应在什么条件下发生？
6. 哪些方法可以直接迁移到 z code + GM 5.2，哪些需要修改 Agent 实现？
7. 完整 Agent Skill（SKILL.md、references、scripts）能否作为低 Token 控制策略的载体？

## 2. 检索来源与检索式

主要来源：arXiv、ACL Anthology、OpenReview、ACM/会议论文官方页面、作者项目页。行业资料仅用于解释工具实践，不作为核心因果证据。

主要英文检索式：

```text
("coding agent" OR "software engineering agent") AND
("token efficiency" OR "cost efficiency" OR "token consumption")

("repository-level code generation" OR "code repair") AND
(context OR retrieval OR pruning OR compression)

("coding agent" OR "code generation") AND
(planning OR verification OR retry OR "early termination") AND
(cost OR token OR efficiency)

("software engineering agent") AND
(underspecified OR clarification OR "human in the loop")

("agent-computer interface" OR "tool interface") AND
(software engineering OR coding)

("agent skills" OR "SKILL.md") AND
("token efficiency" OR cost OR context OR coding)
```

采用了两轮滚雪球：从 2024 年 SE Agent 综述和 SWE-agent、Agentless 等基础论文向后追踪；再从 2026 年 token/cost 论文的参考文献向前追踪。

## 3. 纳入、排除与证据分级

纳入条件：

- 研究对象与代码生成、代码修复、仓库级 Coding Agent 或相近的工具型 Agent 直接相关；
- 方法在固定基础模型时仍然有意义；
- 至少报告任务质量，或报告 token、API 调用、成本、延迟、交互轮次之一；
- 方法和评价设置足够清晰，可以判断适用条件。

排除条件：

- 主要贡献是训练、微调、蒸馏、量化或更换模型；仅当它能界定运行时 Skill 文本开销时作为边界材料保留；
- 只比较模型排行榜，无法分离模型与操作流程的影响；
- 只给主观经验，没有任务质量或资源指标；
- 与仓库级 Coding 的迁移关系过弱。

证据分级：

- **A（直接证据）**：Coding Agent/代码任务；同时测质量与 token/成本；有对照或消融。
- **B（机制证据）**：Coding Agent/代码任务；清楚验证某个机制，但 token 只用成本、轮次或上下文长度间接表示。
- **C（迁移证据）**：通用 LLM 压缩、评测或相邻任务；需要在 z code 场景重新验证。

## 5. 解释边界

- 多数直接研究使用 SWE-bench 系列，绝对成功率受测试缺陷和训练污染影响。2026 年的官方审计也指出这一问题，因此本报告主要采用同一论文内部的相对差异，不把排行榜数字视为普遍能力结论：[OpenAI 审计说明](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)。
- “美元成本下降”不等于“token 下降”。缓存定价、输入输出价格和模型路由都会改变费用；只有论文报告 token 时才作为直接 token 证据。
- 代码补全、函数级生成与仓库级自主 Agent 的操作路径不同。前两者的结果只作为机制证据。
- 2026 年论文较新，部分仍是预印本或首次发表，证据成熟度低于经过多次复现的结论。

## 6. 下一轮检索缺口

1. z code/GM 5.2 是否公开 token 计量、上下文压缩和历史管理机制。
2. 中文需求描述与英文需求描述对 Coding Agent 的影响。
3. 团队真实任务中，用户主动分解与 Agent 自主分解的直接比较。
4. 在固定模型、固定工具链下同时操纵“指令—流程—人机交互”的研究仍然很少。
5. 尚缺在固定 Coding Agent 上，用一个完整 Skill 同时治理冗余上下文、无进展循环和非自适应资源分配的端到端对照研究。
