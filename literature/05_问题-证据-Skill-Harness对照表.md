# AI Coding 低 Token：问题—证据—Skill—Harness 对照表

日期：2026-07-21  
适用场景：固定 z code + GM 5.2  
状态：候选设计，不是已验证 SOP

## 1. 研究定位

本项目关注的不是“把 Prompt 写短”，而是三个端到端 Token 浪费机制：

1. 当前决策不需要的历史、代码和工具输出仍进入上下文；
2. Agent 继续执行，但没有新增证据或可验证进展；
3. 规划、搜索、验证、重试与停止策略不随任务状态调整。

完整 Skill（SKILL.md、references、scripts）用于快速实现和验证控制策略。Skill 能软约束模型行为并通过 scripts 提供部分确定性能力；需要精确观测、拦截或强制执行的机制在验证后下沉至 z code Harness。

## 2. 总对照表

| 问题 | 直接诊断证据 | 已有论文方案 | Skill v0.1 可实现 | 需要 Harness 下沉 | 主要验收指标 |
|---|---|---|---|---|---|
| 冗余上下文 | How Agents Spend、Tokenomics、SWE-Pruner | 任务相关行级裁剪、层级定位、旧 observation 折叠、错误驱动检索 | 规定先搜索后局部读取；按状态加载 references；脚本裁剪日志、记录内容哈希 | 模型调用前的上下文选择；自动 observation 去重/折叠；真实 token/cache 统计 | input token、cache read/write、重复读取率、成功率 |
| 无进展循环 | How Agents Spend、SWE-agent、EET | 提前终止、guardrail、状态保存、选择性重试 | 维护“假设—动作—结果—新证据”账本；检测相同错误/相同读取；连续无进展触发换路 | 跨轮动作事件流；强制停止/换路；学习式 EET；可靠状态持久化 | 无进展轮数、API 调用数、失败轨迹 token、成功率 |
| 非自适应资源分配 | How Agents Spend、PaT、Reason-Code、Runtime-Structured | 失败后规划、条件式搜索、只重试失败部分、分级验证 | 用状态机选择轻量/标准/深入路径；先跑最相关测试；失败或跨模块才升级 | 动态 token/轮次预算；基于实时成本和进展的策略路由；阶段级硬上限 | 每阶段 token、规划触发率、测试成本、成功调整后成本 |

## 3. 问题一：冗余上下文

### 论文已经验证了什么

- SWE-Pruner：任务相关、结构保持的代码裁剪可在其设置中降低 23%–38% token，并轻微提高成功率。
- SWE-agent：简洁但充分的工具反馈、旧 observation 折叠和 guardrail 有助于控制轨迹。
- Agentless：仓库—文件—符号—代码行的层级定位优于直接加载大范围文件。
- RepoCoder/CoCoGen：根据第一次生成、编译或测试反馈补充目标上下文，而不是无目标扩大读取范围。
- SkillReducer：Skill 自身也会制造上下文浪费；核心规则与按需 references 的渐进披露可减少 Skill 输入开销。

### Skill 原型规则

```text
先定位结构和符号
→ 读取支持当前假设的最小代码范围
→ 工具输出只保留可行动片段
→ 记录已读内容的路径、范围和版本哈希
→ 内容未变化时引用旧结论，不重新展开全文
→ 只有新错误或新假设出现时扩大上下文
```

### 边界

- “最小充分”不是字符最少；必须保留语法、依赖和修改锚点。
- SkillReducer 证明的是 Skill 自身优化，不能代替仓库代码 observation 管理。
- 通用自然语言压缩器直接压缩源码存在质量反例。

## 4. 问题二：无进展循环

### 论文已经验证了什么

- EET：基于历史经验提前终止，平均降低约 30% 输入 token，最大解决率损失 0.2 个百分点。
- Runtime-Structured：静态分解可能因级联重跑更贵；保存已验证状态、只重试失败子任务才降低 retry token。
- SWE-agent：成功轨迹通常更早结束，高预算失败轨迹常拖得更久。

### 有效进展定义

满足至少一项才算新增有效进展：

- 错误或失败测试发生有解释力的变化；
- 通过测试数量增加；
- 根因候选被证实或证伪；
- 问题范围缩小到更少文件、符号或输入；
- 发现此前未知但相关的依赖、调用方或约束；
- 得到更小且稳定的复现；
- 修改通过新的静态、单元或集成验证。

以下不算新证据：再次读取未变化的相同内容、相同命令得到相同错误、围绕同一未经验证假设做近似修改。

### Skill 原型规则

```text
每轮写入 progress ledger
→ 对比上一轮动作、错误、测试和假设
→ 有新证据：更新状态并继续
→ 无新证据：累计 no_progress_count
→ 达到阈值：停止当前路径
→ 选择重定位、缩小复现、回滚/简化补丁或请求需求决策
```

### 边界

- “失败”不等于“无进展”；能排除假设的失败有价值。
- 简单固定阈值只能作为弱版本，不能复制 EET 的学习式效果。
- 最大轮数是安全兜底，不等于有效的无进展检测。

## 5. 问题三：非自适应资源分配

### 论文已经验证了什么

- PaT：直接尝试失败后再规划，优于所有任务预付相同规划成本；仓库级迁移仍需验证。
- Reason-Code：greedy 失败后才增加执行反馈搜索，优于无条件支付固定采样成本。
- Runtime-Structured：选择性重试优于级联重跑。
- Agentless/PatchPilot：阶段化流程有助于控制成本，但阶段必须有进入与退出条件。

### Skill 原型状态机

```text
任务与验收检查
→ 低成本定位
→ 最小上下文
→ 局部修改
→ 最便宜且最相关的验证
   ├─ 通过：按风险决定是否扩大回归，然后结束
   ├─ 失败且有新证据：定向补充上下文并继续
   ├─ 跨模块/高风险：升级规划与验证
   ├─ 无进展：停止当前路径并换路
   └─ 缺少用户意图：集中询问一次
```

### 边界

- 不反对固定最大预算；它仍是防止失控的硬上限。
- 反对的是所有任务使用相同规划深度、搜索范围、验证范围和重试策略。
- 简单任务“先尝试”仍需最低成本验证，不能把省 token 变成跳过质量检查。

## 6. Skill 文件职责草案

```text
token-efficient-coding/
├── SKILL.md
├── references/
│   ├── context-policy.md
│   ├── progress-policy.md
│   └── validation-policy.md
└── scripts/
    ├── compact-output
    ├── detect-duplicate
    ├── progress-ledger
    └── summarize-state
```

| 组件 | 只负责什么 | 不应该包含什么 |
|---|---|---|
| SKILL.md | 触发条件、核心状态机、关键判断、停止与升级规则 | 长篇论文解释、所有例子、完整参考资料 |
| references | 仅在相应状态下读取的详细策略、反例和任务模板 | 默认一次性全部加载的重复说明 |
| scripts | 日志裁剪、哈希去重、状态记录、确定性比较 | 需要模型判断的业务意图或根因推理 |
| Harness | 上下文组装、事件流、token/cache 观测、强制预算和终止 | 可频繁变化且尚未验证的研究规则 |

## 7. 当前证据能与不能支持的主张

可以支持：

- Skill 是可复用程序知识和工作流的现实载体；
- 聚焦、渐进披露的 Skill 可以减少其自身上下文开销；
- 上下文裁剪、提前终止、选择性重试和条件式规划分别存在论文证据；
- 在 z code 上做完整 Skill 的配对验证具有明确研究依据。

不能支持：

- 只要启用 Skill 就会减少端到端 token；
- 把三类规则写进 Skill 后，模型一定遵守；
- 现有论文的节省比例可以直接套到 GM 5.2；
- Skill 文件越短越好；
- 固定最大轮数应该被取消。

## 8. 第一轮验证的最小比较

在模型、Zcode 版本、工具权限、仓库 commit、任务和验收器固定时比较：

1. Baseline：不加载研究 Skill；
2. Skill：加载完整 `token-efficient-coding` Skill；
3. Skill + Harness：只加入已经在第二组显示有效、且需要强制执行的 Harness 机制。

至少分别记录：fresh input、cache read、cache write、output、reasoning、调用次数、工具动作、重复读取/执行、无进展轮数、任务通过与人工介入。最终报告成功率约束下的端到端 token，而不是只报告 Skill 文件长度或单轮 prompt token。
